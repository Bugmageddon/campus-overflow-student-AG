## 团队价值观
1. 代码提交前本地跑通测试，不提交烂代码
2. 遇到问题 2 小时内求助队友，不闷头死磕
3. PR 提交后 24 小时内完成评审
4. 坦诚反馈，对事不对人

## 沟通约定
- 日常沟通：qq群
- 集中开发：在线上qq聊天修补代码,及时在宿舍解决关键问题
- 紧急联系：直接打电话

## 开发规约
- 分支命名：feature/功能描述、fix/问题描述
- Commit 格式：
    - feat: 新增功能
    - fix: 修复 bug
    - docs: 文档变更
    - test: 测试相关
    - refactor: 重构
- PR 规则：至少 1 人 review 并 LGTM 后才能合并
- main 分支禁止直接 push，所有改动必须走 PR

## 完成定义 (DoD)
- [ ] 代码通过本地测试
- [ ] PR 评审通过（至少 1 人 LGTM）
- [ ] PO 验收通过（对照 Gherkin 场景手动测试）
- [ ] 无 TODO 残留
