\# ADR-009 渐进式质量门禁



\## 背景



starter 中 Q\&A、Reputation、Discovery 三个上下文仍有 38 个 TODO 测试，

全量 `mvn test` 必然失败，导致 Sprint 0 的 develop 分支无法保持绿色。



\## 决策



Sprint 0 的 CI 只强制以下检查：



\- `co-shared-kernel` 单元测试

\- `co-identity` 五层单元测试

\- `ArchitectureTest` 架构约束

\- 前端 typecheck + build



`co-qa`、`co-reputation`、`co-discovery` 的失败测试暂不阻塞合并，

但测试报告仍归档，便于后续 Sprint 逐步纳入门禁。



\## 后果



\- develop 在 Sprint 0 可以保持绿色；

\- 未实现上下文的失败仍然可见，不会被隐藏；

\- Sprint 2 起把 Q\&A 纳入门禁，Sprint 3 纳入 Reputation/Discovery，

&#x20; Sprint 4 恢复集成测试与覆盖率门禁。



\## 被否决的方案



\- 跳过全部测试：失去门禁意义；

\- 删除或放宽已有测试：违反学术诚信；

\- 等全部实现后再开 CI：Sprint 0 无法验收。
